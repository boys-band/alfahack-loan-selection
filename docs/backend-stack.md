# Обязательный стек backend

Шесть backend-сервисов — applications, catalog, verification, decision, agreements и disbursement — реализуются на **Java 21 для JVM**. Требование распространяется на API, worker, предметную логику и доступ к данным.

## Реализация и сборка

- Production-код сервисов пишется на Java (`.java`). Kotlin, Scala и другие языки JVM не заменяют Java в реализации сервисов.
- Java-фреймворк выбирает исполнитель; он должен поддерживать Java 21 и существующие HTTP/SQL-контракты. Использовать отдельный Python/Node.js backend для части бизнес-логики нельзя.
- Сборка всех шести сервисов — Gradle Wrapper **8.14.3** с проверкой SHA-256 дистрибутива. В каждом сервисе явно задана целевая Java 21; зависимости и плагины имеют фиксированные версии либо управляются зафиксированным BOM. Динамические версии и SNAPSHOT для сдаваемой сборки не использовать. Корневая composite build объединяет сервисы, сохраняя их независимую сборку.
- Dockerfile собирает сервис с JDK 21 и запускает на JVM 21; версии образов фиксируются точным тегом/digest. Сборка и запуск не требуют установленной Java на машине проверяющего, если используются Docker-команды из README.
- Существующие Makefile-цели `test`, `test-integration`, `build` вызывают соответствующие команды Java-сборки. Применяются настоящая PostgreSQL и согласованные миграции.
- Стиль Java: Spotless **8.0.0** и google-java-format **1.28.0**, режим Google, UTF-8, LF. `./gradlew spotlessApply` исправляет код, `./gradlew spotlessCheck` проверяет; `build` включает проверку стиля. Проверяются Java-исходники и тесты, включая нестандартные каталоги disbursement. Форматтер и его версия должны совпадать во всех сервисах и IDE.
- Денежные суммы остаются целыми рублями; расчет платежа/нагрузки реализуется через `BigDecimal` с точностью и округлением из [workflow](workflow.md). Для UTC-времени использовать типы `java.time`; формат JSON сохраняется по контракту.

Это требование не меняет OpenAPI v2, JSON Schema, SQL, границы владения данными, идемпотентность и правила восстановления. Каждый сервис по-прежнему запускается независимо и обращается к соседям по HTTP.

## Frontend и вспомогательные инструменты

Frontend остается браузерной SPA на TypeScript. Его спецификация `docs/frontend-specification.md` доступна в main и ветке frontend.

Скрипты проверки контрактов/БД и генерации ER-схем могут оставаться на Python; SQL-миграции — на SQL. Они являются инструментами разработки, а не реализацией backend-сервисов.
